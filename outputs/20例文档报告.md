## 🐛 关键 Bug 识别

### Bug #1: Circuit Breaker 过于敏感 ⬅️ **已修复**
- **现象**: Circuit breaker 在 2 次 timeout 后 trip，导致后续 LLM 调用全部失败
- **日志**: `LLM circuit breaker TRIPPED after 2 timeouts`
- **影响**: 每个 case 仅 4 次 LLM 调用，大量组件被跳过
- **修复**: 在 `configs/default.yaml` 中设置 `circuit_breaker_max_timeouts: 6`

### Bug #2: Query Generation 无 Fallback
- **现象**: LLM 返回 None 时 `_llm_title_queries` 返回空列表
- **日志**: `LLM title queries: no valid response, got=NoneType`
- **影响**: title_like 路由无查询生成
- **修复**: 添加 `_heuristic_title_fallback` 函数提取 QueryPlan 信息生成备选查询

### Bug #3: Reference Expansion 404 浪费 ⬅️ **已修复**
- **现象**: OpenAlex reference_expansion 花费 203s / 180 次调用，几乎全部返回 404
- **日志**: `OpenAlex work expansion failed for id=...: HTTP Error 404`
- **影响**: 严重消耗 provider_time_budget，导致后续查询被跳过
- **修复**: 在 `_expand_works` 中缓存 404 响应，避免重复请求 dead IDs

### Bug #4: Circuit Breaker 恢复过慢
- **现象**: 即使后续成功，timeout 计数只减少 1
- **影响**: 一旦 trip，很难恢复
- **建议**: 考虑增加恢复速度或使用指数衰减

### 关键 Bug 确认

#### Bug #4: DeepSeek API 严重不稳定 🔴 **新问题**
- **现象**: 每个 case 都有多次 `HTTPSConnectionPool read timed out`
- **影响**: 5个case共8次 LLM 失败，导致大量组件跳过或降级
- **根本原因**: API 提供商网络不稳定或高峰期限流

#### Bug #5: Circuit Breaker 逻辑缺陷 🔴
- **现象**: Circuit breaker 阈值从 2 改为 6，但 timeout 仍然严重影响系统
- **问题**: 即使不 trip，每个 LLM 调用都花费 25s+ 等待超时，拖慢整体流程
- **建议**: 需要更短的 LLM timeout + 快速失败机制
